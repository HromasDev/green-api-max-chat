# Тестовое задание на должность «Фронтенд разработчик React»

В рамках тестового задания требуется разработать пользовательский интерфейс для отправки и
получения сообщений в MAX.

**Время на выполнение задания:** 5 дней

## Требования

1. ✅ Разработан пользовательский интерфейс для отправки и получения сообщений в MAX.
2. ✅ Используется сервис GREEN-API: https://green-api.com/max
3. ✅ Реализована отправка и получение только текстовых сообщений.
4. ✅ За прототип интерфейса взят внешний вид чата: https://web.max.ru/ — двухколоночный layout
   (список чатов слева, окно переписки справа), пузыри сообщений, тёмно-зелёный акцент.
5. ✅ Интерфейс максимально простой: логин, список чатов, окно переписки, поле ввода — без лишних
   функций.
6. ✅ Отправка сообщений — метод [SendMessage](https://green-api.com/v3/docs/api/sending/SendMessage/).
7. ✅ Получение сообщений — [technology-http-api](https://green-api.com/v3/docs/api/receiving/technology-http-api/)
   (`receiveNotification` / `deleteNotification`, поллинг на клиенте).
8. ✅ Использован React (19) + TypeScript.

## Ожидаемый результат

- ✅ Пользователь переходит на сайт чата и вводит `idInstance`/`apiTokenInstance` — `/login`,
  `getStateInstance` проверяет, что инстанс авторизован в MAX.
- ✅ Пользователь вводит номер телефона получателя и создаёт новый чат — форма в сайдбаре,
  `phoneToChatId` собирает `chatId`.
- ✅ Пользователь пишет и отправляет текстовое сообщение — `SendMessage`, сообщение отображается
  оптимистично.
- ✅ Получатель отвечает в MAX — уведомление вычитывается поллингом `receiveNotification` и чат,
  если он не был создан вручную, появляется в списке автоматически.
- ✅ Пользователь видит ответ в чате.

## Как проверялось

Задание разрешает замену MAX на WhatsApp или Telegram, если с MAX не получается. Живая проверка
интеграции сделана через **Telegram**: авторизация инстанса GREEN-API через токен Telegram-бота
(создан через `@BotFather`) — это не требует привязки личного аккаунта по QR, в отличие от
MAX/WhatsApp. Код при этом не завязан на конкретный мессенджер: он работает с GREEN-API как с
единым REST-контрактом (`sendMessage` / `receiveNotification` / `deleteNotification` /
`getStateInstance`), канал выбирается только на уровне инстанса в личном кабинете.

Сценарий проверки:

1. Второй (тестовый) Telegram-аккаунт первым пишет боту любое сообщение — это создаёт чат на
   стороне Telegram (Bot API не позволяет боту писать первым тому, кто с ним ещё не общался).
2. Приложение вычитывает это сообщение через `receiveNotification`, чат с этим `chatId`
   автоматически появляется в списке слева (см. `features/receive-messages`).
3. Дальше переписка идёт в обе стороны обычным образом: `SendMessage` из приложения,
   `receiveNotification` — на входящие.

Форма «новый чат по номеру телефона» из требований задания рассчитана на MAX/WhatsApp, где чат
действительно адресуется по номеру; для Telegram-бота роль этой формы играет шаг 1 выше.

## Осознанные допущения

- **Формат `chatId` для MAX/WhatsApp.** GREEN-API не публикует для MAX отдельный формат
  идентификатора чата в открытой части документации — используется тот же принцип, что и для
  WhatsApp: цифры номера в международном формате + суффикс `@c.us` (см. `src/shared/lib/phone.ts`).
  Если у конкретного инстанса суффикс окажется другим, поменять нужно только эту функцию.
- **Telegram-бот не может писать первым.** Ограничение Telegram Bot API, не GREEN-API: сообщение
  от бота к пользователю возможно только после того, как пользователь сам написал боту хотя бы раз.
  Поэтому в проверке чат создаётся автоматически по первому входящему, а не через форму по номеру.
- **История переписки.** GREEN-API отдаёт по HTTP только _новые_ уведомления из очереди — истории
  диалога по REST нет. Все сообщения, показанные в приложении, — это то, что реально прошло через
  него; история сохраняется между перезагрузками в `localStorage` (`entities/chat`), но не
  подтягивается с сервера GREEN-API.
- **Один активный поллинг на вкладку.** Пока открыта `/chat`, приложение непрерывно вызывает
  `receiveNotification` в цикле (с паузой при сетевой ошибке) и сразу же `deleteNotification` —
  ровно так, как описан HTTP API в документации.
